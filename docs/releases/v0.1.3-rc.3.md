## Functional correction since rc.2

The Gateway integration now follows the required separation of responsibilities:

1. The host observer alone accesses the VPN Gateway HTTPS read-only status
   API, using an approved token and verified TLS CA. It verifies the
   host MAC/IP, route, lease freshness, matching TCP/UDP ports and Gateway.
2. The observer atomically publishes a root-owned mode 0600 JSON file.
3. Stremio's reconciler consumes **only** the local observation
   (`SOURCE=observation`), verifies schema, owner, permissions, identity,
   freshness and lease validity, then updates `.env` and recreates
   **only the Stremio container** after the observed port changes.
4. A simulated recreation failure or an unhealthy newly started container
   triggers rollback to the former `.env`, published port and Docker state.
5. The reconciler refuses silent success if Docker and `.env` disagree.
   Direct API access from the reconciler has been removed.

No bearer token is embedded in the repository or downloadable artifacts.

  provider-port rotation test before enabling this workflow.
- Validate live provider lease renewal, .env change, Stremio-only recreation,
  health checks, rollback, post-reboot recovery and absence of DNS leaks.
- Check TCP/UDP inbound peer reachability independently from NAT-PMP mapping.
- Validate real IPTV, embedded subtitles, audio and TV client playback.
- Promote the sanitised screenshots into both repositories with matching
  SHA256 before activating the image gallery in the README.
- Review administrative LAN restrictions; never expose privileged
  Docker management directly to the public Internet.

The simulated observer and rollback tests do **not** establish external
port reachability or completion of the operational Gateway acceptance.
