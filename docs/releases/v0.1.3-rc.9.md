# Stremio Standalone v0.1.3-rc.9 — Fresh-install VPN integration and passwordless LAN WebAdmin

- First-time WebAdmin HTTPS is accessible without a login exclusively from the detected private /24-or-narrower LAN. The direct backend stays bound to loopback. Optional Basic authentication remains available by explicit access-policy.
- Automatic Gateway detection by the actual kernel default IPv4 next hop. If Gateway Multi v1.0.8 has authorised the host identity for TCP/UDP port forwarding, a host-side read-only observer validates MAC/IP, policy, identical TCP/UDP mapping, lease freshness and ownership. No bearer token is issued or copied.
- First contact uses *trust on first use*: TLS certificate IP SAN and its SHA-256 are verified/pinned to root-only state; a later unexpected certificate change rejects the observation.
- Only Stremio's own reconciler updates `STREMIOSRV_BT_LISTEN_PORT` and recreates the Core container with a health and VAAPI check. Existing profiles/Docker volumes remain intact.
- If the Gateway is not present, authorization is revoked or no fresh NAT-PMP lease exists, the Core returns to default TCP/UDP port `6881` after at most 120 seconds of grace for transient renewals. The host does **not** lift any Gateway routing or firewall blocks.
- Existing independently authenticated Gateway observers remain compatible and take precedence.

## Security conditions

The automatic enrollment trusts an IP/MAC-scoped service on an isolated management LAN. IP/MAC can be spoofed on poorly controlled L2 networks; TOFU cannot authenticate the server at the very first connection against an active MITM. Do not use this mode on untrusted networks or expose the management/status ports on the WAN. Prefer pre-approved PKI plus dedicated bearer-token mode where stronger trust is required.

## QA scope

Verified operationally with VPN Gateway Multi 1.0.7 plus the candidate restricted host endpoint: real NAT-PMP port 62743 was observed, applied, and the Core stayed healthy with /dev/dri/renderD129. A simulated missing authorisation triggered rollback to TCP/UDP 6881 and later automatic recovery to 62743 by the reconciliation timer. This does not establish real Internet peer reachability or long-term lease change/reboot acceptance.
