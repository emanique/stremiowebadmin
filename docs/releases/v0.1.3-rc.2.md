# Stremio Server WebAdmin Standalone v0.1.3-rc.2 — QA pre-release

**Candidate, not a stable release.** Supersedes v0.1.3-rc.1.

## Source and supported distribution

- Private development source: `emanique/StremioServerWebAdmin` (the sole development authority).
- Public source and installable clone: `emanique/stremiowebadmin`.
- Standalone distribution version: `0.1.3-rc.2`.
- WebAdmin version: `3.0.14`; Stremio core version: `1.6.34`.
- The public repository contains **no GitHub Actions** and no DEV-only promotion script.
- Images build from source and declared registries; no local-only images are required.

## Changes since rc.1

1. Subtitle-extraction FFmpeg failures have bounded diagnostic categories such as
   `incomplete_or_invalid_media`, `subtitle_decode_error`, or
   `subtitle_stream_unavailable`. The original FFmpeg stderr, media URLs and
   tokens are never printed. This is **diagnostic instrumentation**, not a
   guarantee that extracting subtitles from incomplete torrents will succeed.
2. A clean installation from the public rc.1 tag passed on a fresh Debian 13
   KVM VM, with images built from external registries, both Docker services
   healthy, a valid HTTPS administrator authentication boundary, and automatic
   recovery after reboot. The installer and architecture are unchanged in rc.2.
3. README source/release status and QA evidence updated, with the exact current
   Python regression count.

## Stable-release blockers

- Provision a dedicated read-only Gateway status token on the Stremio host
  via an authorised secret-management channel. Prove **real** lease rotation,
  `.env` update, controlled container recreation, rollback on failed health,
  and reboot recovery.
- Verify external TCP/UDP BitTorrent reachability independently of internal
  NAT rules.
- Validate IPTV audio, codec and embedded subtitles on the target TV clients.
- Upload the approved screenshot gallery into `docs/screenshots/` in both
  repositories, with byte-identical image content.
- Complete administration/LAN access review; Nginx Basic authentication alone
  is not a reason to expose Docker control to the public Internet.

Never interpret a passed clean installation or an FFmpeg diagnostic improvement
as acceptance of the remaining functional and network-security requirements.
