# AI subtitle compatibility: WebPlayer + Stremio desktop app

## Source contracts (checked 2026-11-17)
- Stremio Core Rust: `src/types/resource/subtitles.rs` defines `id`, `lang`, `url`, optional `label` and `fonts`.
- WASM player projection: `stremio-core-web/src/model/serialize_player.rs` adds `addonSubtitleId` and `origin`. The UI-visible `id` is generated by the Core and **must not** be parsed as our addon ID.
- `src/models/player.rs::subtitles_update` asks the addon for subtitles using its selected video resource and optional `videoHash`, `videoSize`, `videoFilename`. `videoHash` is not guaranteed to be a BitTorrent infohash.
- The Core has `ActionPlayer::TimeChanged`, `Seek`, `PausedChanged`, `Ended`, but the standard addon subtitles HTTP contract does not transmit those playback actions to addon servers.

## Current WebPlayer
The local bundle hook receives an **explicit** AI subtitle selection and an actual player clock. It resolves the track's private capability URL, then invokes:
- `POST /ai-subtitles/{token}/demand/start` with exact `infohash`, `fileIndex`, `audioIndex` and `positionSeconds`;
- `POST /demand/{session}/heartbeat` for playhead updates and seeks;
- `GET /demand/{session}/subtitles.srt` for a refreshable overlay;
- `POST /demand/{session}/stop` when deselected, unloaded or ended.
The independent subtitle track remains prefetch-safe: listing/GET alone does not start transcription.

## Desktop Stremio app: integration contract
An **unmodified** Stremio desktop app can install the manifest, show a normal SRT track and download a snapshot. It does not guarantee (1) running the WebPlayer hook, (2) polling an SRT again, or (3) posting a playhead clock/seek/stop to this addon. Do not promise real-time on-demand translation from installation alone.

For full feature parity, a separately authorised/packaged desktop companion or an officially supported client extension must:
1. Subscribe to an explicit user selection of the AI track (identify by `origin`, `addonSubtitleId` or verified capability URL; never trust only the Core-generated `id`).
2. Resolve an *exact* torrent infohash and file index from server-owned media data (do not confuse `videoHash`/IMDB with infohash; ambiguous mappings must fail closed).
3. Send monotonic or seek-aware absolute **movie** time, including pause/buffering/resume; normal playback MUST NOT be inferred from GET requests.
4. Call `demand/start`, bounded heartbeat, refresh snapshot SRT in a client-supported way, and stop on deselection/end/unload. Prevent duplicate processing across multiple clients by shared hash/file/chunk cache, separate sessions/playheads.
5. Use TLS and token-based least privilege. Never log URLs, full tokens, movie titles or media paths. Restrict LAN access and avoid a globally exposed unauthenticated playback-control API.
6. Keep the default client addon compatible even without a companion: it can display existing cached SRT and an honest preparing placeholder, but cannot claim automatic generated playback.

## Acceptance criteria
- WebPlayer: AI explicitly selected; session starts once; seek sends absolute clock; different sessions play same media at distinct positions; silence block does not stall subsequent 30s chunks; native/other subtitle renderers remain unchanged.
- Desktop app 6.1.1: manifest and track visible; verify a normal snapshot is playable; separately test a real companion event stream before declaring auto-generation parity.
- With no companion or no reliable source identity: no background Whisper, no inferred seek, no periodic generation; explicit limitation shown.
- Switching content/hash or deleting a torrent invalidates associated AI cache under the same purge rules as existing cache.
- IPTV, torrent transport, VPN and WebAdmin behaviour unchanged.
